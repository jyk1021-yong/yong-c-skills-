# 만들기 지문 (용개발)

"용개발 켜줘" 뒤에 이 양식을 채워서 보내면, 무엇을 만들지부터 검사와 보고까지 한 번에 진행합니다. 작업 md는 채워진 내용을 바탕으로 Claude가 만듭니다.

```
[만들기]
- 무엇을: (기능 / 모듈 / 화면 / 도구 / 스크립트 중 하나, 한 문장)
- 왜: (이걸 만들어서 해결하려는 일)
- 어디에: 저장소 owner/repo, 브랜치 (새 저장소면 이름과 설정)

[동작]
- 입력: (형식, 예: "2026-10-25" 또는 "2026.10.25")
- 출력: (형식, 예: "2026.10.25")
- 예시: (입력 → 출력을 2~3개)
- 잘못된 입력: (무엇을 돌려줄지, 예: 빈 값 또는 오류 메시지)

[범위]
- 포함: 
- 제외: 

[제약]
- 바꾸면 안 되는 것: (기존 화면, 데이터, 공개 주소 등)
- 쓰지 말 것: (라이브러리, 방식 등)
- 기존 코드 참조: (파일 경로가 있으면 적기)

[완료 기준]
- [ ] 
- [ ] 

[검사]
- 단위 테스트: (무엇을 확인할지)
- 기존과 비교: (바뀌기 전후 같아야 하는 것)
- 실행 확인: (브라우저 또는 명령으로 확인할 방법)

[구조]
- 층: 화면 → 모듈 (역방향 금지). 모듈은 순수 함수, 현재 시각 같은 값은 인자로 받기
- 모듈 위치: src/modules/<이름>/ (진입점 index)
- 설계 선택이 생기면 architecture-decision-records로 남기기

[보고]
- 변경 파일 목록, 검사 출력 (통과/실패 그대로), 연결도 (어떤 파일이 어떤 파일을 부르는지), 남은 일
```

## 채우는 요령

- 빈 칸은 비워 둬도 됩니다. 단, **저장소, 목표(무엇을), 완료 기준**은 꼭 채워야 시작합니다.
- 입출력 예시가 있으면 테스트를 바로 만들 수 있어서 가장 빠르게 진행됩니다.
- 기존 코드를 고치는 작업이면 "바꾸면 안 되는 것"을 꼭 적어 주세요.
